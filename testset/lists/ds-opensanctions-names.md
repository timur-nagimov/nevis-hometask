# ds-opensanctions-names

Автор: Claude subagent (built mechanically from the UK sanctions list; blind to every search design), 2026-11-20.

Client name search on real names from the UK sanctions list (built mechanically). Source: FCDO UK Sanctions List XML https://sanctionslist.fcdo.gov.uk/docs/UK-Sanctions-List.xml, DateGenerated 20/11/2026, Last-Modified Fri, 20 Nov 2026 11:37:31 GMT, sha256 6b558b1981c232efaff3c52e87da32369849163c7948c56646b8f3bdf7befabf (fetched 2026-11-20T16:03:46Z); licence Open Government Licence v3.0. This is the upstream file of the OpenSanctions dataset gb_fcdo_sanctions (version 20261120144740-esw), which was the intended source: data.opensanctions.org resolved to 127.0.0.1 from the build machine, the API needs a key and the matcher pairs need an account, so the pairs were not used either. Each Individual designation is mapped to FollowTheMoney Person properties as OpenSanctions does (name, firstName=Name1, middleName=Name2-5, lastName=Name6, alias = name variations, good-quality aliases and non-Latin names, weakAlias = low-quality aliases, nationality, position, birthPlace, topics=sanction). Corpus: 200 of 4065 individuals, seed 20261120: 140 drawn from entries with a Latin re-spelling or a non-Latin name, 60 from the rest. Client first_name/last_name = firstName/lastName; when either is missing the primary name is split at its last space (single-word names are not sampled); words written in capitals are Capitalised. E-mail is a placeholder '<first>.<last>@example.org' (ASCII, lower case, accents stripped, other characters to '-', a digit appended on collision). Description is built from nationality (as a demonym), positions and the first birth place: '<Demonym> national. Position: ... Born in <town>, <country>.'; social_links are empty. Labels: name queries are relevant to the entry they come from plus clients with exactly the same name words; acceptable = other clients that hold every query word as a substring of some field. Full name (required, must rank first), surname alone when no other client has it (required), surname-first order (expected). Aliases that re-spell the name (each word within 0.7 SequenceMatcher ratio of a name word) and names in other scripts are nice: relevant = every client whose list entry carries that exact name, at least one in the first 5, other results not scored. Description queries (expected): relevant = every client whose description has the value as a whole word, 2-20 clients. Negatives (expected, empty): names of other list entries that are not clients but share a surname with a client while the first names clearly differ (no word pair within 0.6 ratio), or share a first name and have a surname of 0.7-0.85 similarity; they have no common name or birth date with the look-alike, and their words are not all found in any client; must_not = the look-alike clients. The matcher pairs were not reachable, so no analyst judgements were used. The people are real, public sanctions-list entries. Built by research/datasets/build/ds_opensanctions_names.py (seed 20261120).
