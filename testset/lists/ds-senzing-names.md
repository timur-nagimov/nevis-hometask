# ds-senzing-names

Автор: Claude subagent (dataset import, labels from the Senzing answer key and the nickname table), 2026-11-20.

Client name and e-mail search cases converted from two open datasets. (1) Senzing truth sets, demo set (https://github.com/Senzing/truth-sets, commit 68761b692bf5cf8bf0eebd24ef5961e0bb32d25e, files truthsets/demo/customers.csv, watchlist.csv, reference.csv and actual_truthset_key.csv, Apache-2.0): mock KYC records with hand-curated name variations and an answer key grouping records into entities. (2) carltonnorthern/nicknames (https://github.com/carltonnorthern/nicknames, commit ed160b3af2d17e1af8ebd570f10a10e4dade4ff4, file names.csv, Apache-2.0): canonical given names and their nicknames. Corpus: one client per answer-key entity that has a CUSTOMERS person record with a Latin-script first and last name (64 of 85 entities; 13 entities have only watchlist/reference records). Representative = such record with the lowest RECORD_ID; first_name/last_name as recorded (CUSTOMERS 1058 really has first name Jones, last name Jay); e-mail = the first address found in the entity, else an invented client.<id>@example.com placeholder (30 clients: c002, c007, c008, c009, c010, c011, c012, c014, c015, c016, c017, c019, c020, c021, c024, c025, c026, c027, c028, c029, c030, c031, c032, c033, c036, c037, c039, c040, c044, c045; no query uses them); description = only the representative's ADDR_CITY, ADDR_STATE, ADDR_COUNTRY, CATEGORY and STATUS fields; social_links empty. Queries: names and e-mail addresses of the other records of each entity, typed as an adviser would (full name, distinctive surname alone, e-mail, local part, local@domain-name, domain, native script); relevant = that entity's client (for e-mail queries every client holding the exact address, local part or domain, e.g. the Kusha household shares one address); acceptable = other clients sharing a name word or prefix, a nickname-table first name, or containing the query in e-mail/description; first is set only when the relevant clients are the only ones matching every query word (nicknames via the table). Levels: exact name, first name, surname, e-mail and e-mail fragments = required; punctuation, swapped order, initials and partial compound names = expected; nicknames, typos, other first-name spellings ('name variant'), longer compound surnames and native script = nice (typos and name variants: within_top 5, others ignored). 16 extra nickname queries come from the nickname table (nicknames that occur nowhere in the Senzing files); if an engine uses the same table for synonym expansion those cases are circular. Entities not used: looks like a real person (Vasiliev): 1; no customer record has both a first and a last name: 1; organisation, not a person: 6. Variants left out (7): first initial does not match the client's first name: 1; role mailbox shared by many unrelated entities: 2; surname differs from the client's: 4 (details in left_out). Attribution: contains data from Senzing truth-sets (c) Senzing, Inc. and from the nicknames table by Carlton Northern / Old Dominion University Web Science and Digital Libraries Research Group, both under the Apache License 2.0; records were selected, reformatted and relabelled for this suite. Built by research/datasets/build/ds_senzing_names.py from research/datasets/raw/senzing/.
